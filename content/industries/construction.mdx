## Typical requirements

- A project per site or contract, with tasks people actually update
- Purchase orders for subcontractors and materials
- Site stock that is separate from the main warehouse
- Invoices tied to a milestone or a measured progress step

## Common modules

Project, Purchase, Inventory, and Accounting. Start with one live site. Adding every historical project on day one hides data problems inside the import.

## A first release

Write the as-is path from material request to vendor bill before configuring stages. The [implementation guide](/implementation-guide) is the planning sequence. The [project module](/modules/project) covers tasks and billing style.
