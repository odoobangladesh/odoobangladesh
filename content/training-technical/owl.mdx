Odoo OWL training teaches you to build front-end components for Odoo 17 to 19 with OWL 2, the component framework that powers the web client and Point of Sale: components and templates, props and validation, `useState` and `useRef`, lifecycle hooks such as `onWillStart`, the `useService` hook for ORM and notifications, registering a field widget or client action, declaring assets in the manifest, and deciding when a plain XML view is the better choice. The exercises build a VAT summary widget and a small POS change for a Dhaka pharmacy, because that is the kind of front-end work local clients pay for. It follows the [ORM](/training/technical/orm) topic because every component you write reads data through it.

## Learning outcomes

By the end of this topic you should be able to:

- Write an OWL 2 component with a `static template`, `static props` and a QWeb template using `t-if`, `t-foreach`, `t-on-click` and `t-out`.
- Manage reactive state with `useState`, read DOM nodes with `useRef`, and load data in `onWillStart` and `onWillUpdateProps`.
- Call the server through `useService("orm")` and show feedback through `useService("notification")`.
- Register a field widget in `registry.category("fields")` and use it from a form view with `widget="..."`.
- Register a client action and open it from a menu.
- Declare JavaScript, XML templates and SCSS in `web.assets_backend` and `point_of_sale._assets_pos` in the manifest.
- Patch an existing POS component in Odoo 17 to 19 without copying the whole file.
- Explain to a client why a computed field and a standard view are cheaper than a custom component when they are enough.

## Prerequisites

Complete [module development](/training/technical/module-development) and [ORM](/training/technical/orm). Know modern JavaScript. Run Odoo with `--dev=all` so asset changes reload without a restart. Read the [Point of Sale module](/modules/pos) page before the POS session.

## Practice exercises

**Exercise 1: VAT summary component.** Build a component that shows total sales, output VAT and input VAT for the current month for a hypothetical Chittagong trading company, read through the ORM service. The example uses `searchRead`, whose signature is the same in Odoo 17, 18 and 19; the grouped-read helpers changed between versions, so when you need server-side aggregation call a Python method with `this.orm.call(...)` instead:

```javascript
/** @odoo-module **/
import { Component, useState, onWillStart } from "@odoo/owl";
import { registry } from "@web/core/registry";
import { useService } from "@web/core/utils/hooks";

export class BdVatSummary extends Component {
    static template = "bd_vat_mushak.VatSummary";
    // The action service passes extra props to a client action, and --dev=all validates them.
    static props = { "*": true };

    setup() {
        this.orm = useService("orm");
        this.state = useState({ sales: 0, outputVat: 0, inputVat: 0, loading: true });
        onWillStart(async () => {
            const moves = await this.orm.searchRead(
                "account.move",
                [["state", "=", "posted"], ["move_type", "in", ["out_invoice", "in_invoice"]]],
                ["move_type", "amount_untaxed", "amount_tax"],
                { limit: 5000 }
            );
            for (const m of moves) {
                if (m.move_type === "out_invoice") {
                    this.state.sales += m.amount_untaxed;
                    this.state.outputVat += m.amount_tax;
                } else {
                    this.state.inputVat += m.amount_tax;
                }
            }
            this.state.loading = false;
        });
    }
}

registry.category("actions").add("bd_vat_mushak.vat_summary", BdVatSummary);
```

Write the matching XML template with `t-if="state.loading"`, `t-out` for each amount, and a table that formats amounts as BDT, declare both files in `web.assets_backend`, and add a client action and menu under Accounting Reporting.

**Exercise 2: BIN field widget.** Create a field widget that accepts only digits, shows a red border until 13 digits are entered, and writes the value with `this.props.record.update({ [this.props.name]: value })`. Use it on the partner form with `widget="bd_bin"`.

**Exercise 3: Late return notification.** If today is more than 15 days past the end of the chosen filing period (monthly or quarterly since Finance Act 2026) and no Mushak 9.1 has been marked filed for that period, show a warning notification when the VAT dashboard opens. Use `useService("notification")` and keep the check on the server side in a Python method called through `this.orm.call(...)` or `rpc` (in 17 `rpc` is a service obtained with `useService("rpc")`, in 18 and 19 it is a function imported from `@web/core/network/rpc`).

**Exercise 4: Dhaka pharmacy receipt.** Patch the POS receipt component so each line shows "incl. 15 percent VAT" and the footer shows the pharmacy's BIN. Use the `patch` utility from `@web/core/utils/patch` and declare the file in `point_of_sale._assets_pos`. Test it offline by disconnecting the network and printing a receipt.

**Exercise 5: Decide against OWL.** A client asks for a coloured badge on overdue invoices. Show that a `decoration-danger` attribute on the list view does it with no JavaScript, and write two sentences for the client explaining why that is the better choice.

## Frequently asked questions

### Is OWL the same as React or Vue?

It is a small component framework with similar ideas: components, props, reactive state and hooks. OWL 2 is what Odoo 17 to 19 ship, and the web client, POS and many widgets are built on it. If you know React you will be productive in a week.

### Do I need OWL to be an Odoo developer?

Not for most backend work. XML views, QWeb reports and Python cover the majority of Bangladesh projects. You need OWL when a client wants a custom widget, dashboard, POS screen change or an interactive client action.

### How much JavaScript do I need?

Modern ES modules, classes, async and await, and template literals. The training assumes you can read a Promise chain. No build tool knowledge is needed because Odoo bundles assets itself.

### Did OWL change between Odoo 17 and 19?

OWL 2 is used throughout and the component model (components, props, hooks, templates) is stable. What changed between 17 and 18 is around it: `rpc` moved from a service to a function imported from `@web/core/network/rpc`, the JavaScript test framework moved from QUnit to HOOT, and some field widget props were refined. The exercises use `searchRead` and `orm.call`, which behave the same in all three versions, but check the version before copying a snippet.
